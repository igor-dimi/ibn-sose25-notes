Aufgabe 1

12 points

Threads A and B each produce one result. Neither may enter its combine operation until both results have been produced. The production operations access separate storage; both combine operations only read the completed results.

A programmer proposes:

shared Semaphore done = 0

Thread A:                    Thread B:
    produce_A()                  produce_B()
    signal(done)                 signal(done)
    wait(done)                   wait(done)
    combine_A()                  combine_B()

a) — 3 points

Give an execution that violates the required ordering. Show the relevant semaphore operations and explain precisely which requirement fails.

b) — 4 points

Replace the synchronization with a correct semaphore-based construction.

Give all initial values and both threads’ pseudocode. The production operations must remain able to execute concurrently; neither thread may busy-wait.

c) — 5 points

Consider this independent initialization mechanism for three worker threads:

shared bool ready = false
shared Mutex m = unlocked
shared Condition changed

Worker:
    lock(m)
    if not ready:
        cond_wait(changed, m)
    unlock(m)
    use_configuration()

Initializer:
    build_configuration()
    lock(m)
    ready = true
    cond_signal(changed)
    unlock(m)

All workers must eventually proceed once initialization finishes, regardless of when they start. Spurious wakeups are possible. The configuration remains unchanged after publication.

Correct the synchronization and explain the necessary changes. Also state what cond_wait(changed, m) does with the mutex when waiting and before returning.

Aufgabe 2

18 points

A byte-addressed machine uses:

  • 24-bit virtual addresses;
  • 20-bit physical addresses;
  • 1 KiB pages;
  • two-level page tables;
  • an equal split of the virtual-page number between the two levels;
  • eight-byte entries at both levels.

Each table is allocated in full and occupies exactly its entry storage, with no extra metadata. Non-leaf entries contain physical table-base addresses; leaf entries contain frame numbers and flags.

a) — 3 points

Give the virtual-address field widths and the number of entries and bytes in one table at each level.

b) — 3 points

A process has exactly these allocated virtual pages:

\[ 0,\quad 127,\quad 128,\quad 130,\quad 1023. \]

Only necessary second-level tables are allocated; one root table always exists.

Determine the number of allocated tables at each level and their total memory consumption. Compare this with a full single-level table using eight-byte entries.

c) — 4 points

For one read, the virtual address has:

  • root index \(1\);
  • second-level index \(2\);
  • byte offset \(29\).

The root table starts at physical address 0x1000. Its selected entry points to a table at physical address 0x3000. The selected leaf entry maps to frame 0x2A. All relevant entries are present and permit the read.

Calculate:

  • the virtual byte address;
  • the physical address of the selected root entry;
  • the physical address of the selected leaf entry;
  • the physical address of the requested data.

Use hexadecimal or decimal consistently.

d) — 4 points

The system uses a sequential TLB lookup model:

  • TLB lookup: \(6\,\mathrm{ns}\);
  • each RAM access: \(50\,\mathrm{ns}\);
  • TLB hit ratio: \(0.96\).

All data pages and page-table pages are resident. Ignore other caches, overlap and TLB-update costs. A TLB miss requires a complete two-level walk; no additional TLB lookup is charged afterward.

Calculate the hit time, miss time and expected time for one data read.

Does a TLB miss necessarily imply a page fault? Explain briefly.

e) — 4 points

An independent replacement snapshot has three occupied frames:

Frame Page Reference bit \(R\)
0 A 1
1 B 0
2 C 1

The Clock hand points to frame 0. The actual last-access order, from oldest to newest, is C, A, B. All pages are clean.

Process the reference sequence:

\[ D,\quad B,\quad E. \]

Use these Clock conventions:

  • a hit sets the page’s reference bit to 1 and leaves the hand unchanged;
  • replacement scans cyclically, clearing and passing entries with \(R=1\);
  • the first entry with \(R=0\) is replaced;
  • a loaded page receives \(R=1\), and the hand advances to the following frame.

After each reference, record the frame contents, reference bits, hand position and victim, if any.

Separately, state which page exact LRU would evict for the first reference, starting from the original snapshot.

Aufgabe 1 — 12 points

a) — 3 points

Thread A can consume the permit that it released itself:

Step Operation Semaphore done Consequence
1 A: produce_A() 0 A’s result exists
2 A: signal(done) 1 One permit becomes available
3 A: wait(done) 0 A acquires that permit without blocking
4 A: combine_A() 0 B has not yet produced its result

Thus A enters combine_A() before both results exist.

The shared semaphore counts completed productions, but it does not distinguish whose production has finished.

b) — 4 points

Use a separate completion semaphore for each result:

shared Semaphore a_ready = 0
shared Semaphore b_ready = 0

Thread A:
    produce_A()
    signal(a_ready)
    wait(b_ready)
    combine_A()

Thread B:
    produce_B()
    signal(b_ready)
    wait(a_ready)
    combine_B()

Each thread:

  • finishes its own production before announcing completion;
  • waits for the other thread’s completion before combining.

The production operations can execute concurrently. A signal issued before the other thread reaches its wait remains available as a semaphore permit.

c) — 5 points

Corrected pseudocode:

shared bool ready = false
shared Mutex m = unlocked
shared Condition changed

Worker:
    lock(m)

    while not ready:
        cond_wait(changed, m)

    unlock(m)
    use_configuration()

Initializer:
    build_configuration()

    lock(m)
    ready = true
    cond_broadcast(changed)
    unlock(m)

Two changes are required:

  1. Replace if with while.
    A worker must recheck ready after waking. A spurious wakeup must not allow it to use an unfinished configuration.

  2. Replace cond_signal with cond_broadcast.
    All waiting workers must be allowed to proceed. A single signal could leave other workers asleep indefinitely, since there is no later notification.

cond_wait(changed, m):

  • atomically releases m and begins waiting on changed;
  • reacquires m before returning.

Consequently, a sleeping worker does not retain the mutex needed by the initializer.

Workers that start after initialization find ready == true and do not wait. They do not need a stored notification because the shared predicate remains true.

Aufgabe 2 — 18 points

a) — 3 points

The page size is:

\[ 1\text{ KiB}=2^{10}\text{ bytes}. \]

Therefore, the offset uses 10 bits. The remaining virtual-address bits are:

\[ 24-10=14. \]

Splitting these equally gives:

\[ \boxed{ \underbrace{\text{root index}}_{7\text{ bits}} \quad \underbrace{\text{second-level index}}_{7\text{ bits}} \quad \underbrace{\text{offset}}_{10\text{ bits}} }. \]

Each table at either level has:

\[ 2^7=\boxed{128\text{ entries}}. \]

With eight-byte entries:

\[ 128\cdot8=\boxed{1024\text{ bytes}=1\text{ KiB per table}}. \]

b) — 3 points

Decompose each virtual-page number into its two indices:

Virtual page Root index Second-level index
0 0 0
127 0 127
128 1 0
130 1 2
1023 7 127

Three distinct root entries are used: 0, 1 and 7.

Thus the hierarchy contains:

  • one root table;
  • three second-level tables.

Total table memory:

\[ (1+3)\cdot1024 =\boxed{4096\text{ bytes}=4\text{ KiB}}. \]

A full single-level table requires:

\[ 2^{14}\cdot8 =2^{17}\text{ bytes} =\boxed{128\text{ KiB}}. \]

The sparse hierarchy therefore uses \(1/32\) of the full flat table’s memory.

c) — 4 points

The virtual-page number is:

\[ p=1\cdot128+2=130. \]

The virtual byte address is:

\[ V=130\cdot1024+29 =\boxed{133149} =\boxed{\texttt{0x2081D}}. \]

The root entry is located at:

\[ \texttt{0x1000}+1\cdot8 =\boxed{\texttt{0x1008}}. \]

The leaf entry is located at:

\[ \texttt{0x3000}+2\cdot8 =\boxed{\texttt{0x3010}}. \]

Frame 0x2A has decimal frame number 42. The physical data address is:

\[ A=42\cdot1024+29 =\boxed{43037} =\boxed{\texttt{0xA81D}}. \]

d) — 4 points

A TLB hit requires one TLB lookup and one data-memory access:

\[ t_{\text{hit}}=6+50 =\boxed{56\text{ ns}}. \]

A resident-page TLB miss requires:

  • one TLB lookup;
  • two page-table accesses;
  • one final data access.

Therefore:

\[ t_{\text{miss}}=6+3\cdot50 =\boxed{156\text{ ns}}. \]

The expected access time is:

\[ \begin{aligned} t_{\text{effective}} &=0.96\cdot56+0.04\cdot156\\ &=53.76+6.24\\ &=\boxed{60\text{ ns}}. \end{aligned} \]

A TLB miss does not necessarily imply a page fault. It means the translation is absent from the TLB. A page-table walk may find that the requested page is already resident.

e) — 4 points

The initial state is:

Frame 0 Frame 1 Frame 2 Hand
A, \(R=1\) B, \(R=0\) C, \(R=1\) 0

The completed Clock trace is:

Reference Hit/fault Victim Frame 0 Frame 1 Frame 2 Hand afterward
D Fault B A, \(R=0\) D, \(R=1\) C, \(R=1\) 2
B Fault A B, \(R=1\) D, \(R=1\) C, \(R=0\) 1
E Fault C B, \(R=1\) D, \(R=0\) E, \(R=1\) 0

The scans are:

  • D: clear A’s bit at frame 0; replace B at frame 1.
  • B: clear C’s bit at frame 2; replace A at frame 0.
  • E: clear D’s bit at frame 1; replace C at frame 2.

Starting from the original snapshot, exact LRU would evict C for the first reference, because the stated oldest-to-newest order is C, A, B.

Clock instead evicts B. Reference bits do not encode an exact ordering of last-access times.

Aufgabe 3 — 12 points

a) — 6 points

Non-preemptive SJF

Interval (ms) Running process
0–5 \(P_1\)
5–7 \(P_3\)
7–8 \(P_4\)
8–11 \(P_2\)

At time 5, \(P_2\) and \(P_3\) are ready; SJF selects \(P_3\). \(P_4\) arrives at time 6 but does not preempt it. At time 7, \(P_4\) has the shortest available burst.

Round Robin, \(q=3\text{ ms}\)

Interval (ms) Running process
0–3 \(P_1\)
3–6 \(P_2\)
6–8 \(P_3\)
8–10 \(P_1\)
10–11 \(P_4\)

At time 3, the ready queue after re-enqueuing \(P_1\) is:

\[ [P_2,P_3,P_1]. \]

At time 6, \(P_2\) finishes and \(P_4\) arrives. The queue is:

\[ [P_3,P_1,P_4]. \]

b) — 4 points

For each process:

\[ T_i=\text{completion time}-\text{arrival time}, \]

\[ W_i=T_i-\text{CPU burst}. \]

Completion times:

Process SJF completion RR completion
\(P_1\) 5 10
\(P_2\) 11 6
\(P_3\) 7 8
\(P_4\) 8 11

All following values are in milliseconds:

Process SJF turnaround SJF waiting RR turnaround RR waiting
\(P_1\) 5 0 10 5
\(P_2\) 10 7 5 2
\(P_3\) 4 2 5 3
\(P_4\) 2 1 5 4

Average SJF waiting time:

\[ \overline W_{\mathrm{SJF}} =\frac{0+7+2+1}{4} =\boxed{2.5\text{ ms}}. \]

Average RR waiting time:

\[ \overline W_{\mathrm{RR}} =\frac{5+2+3+4}{4} =\boxed{3.5\text{ ms}}. \]

c) — 2 points

SJF can cause starvation. A long ready process may be repeatedly passed over if shorter processes are available at every scheduling decision.

Round Robin does not cause this form of starvation under the stated assumptions. A queued process has finitely many processes ahead of it, and each receives at most one quantum before leaving the CPU. New arrivals join the tail rather than overtaking it. A process with a finite burst therefore eventually finishes.

b) — 5 points

Destination All matching prefixes Selected prefix Interface

10.88.41.9 10.88.40.0/22; 10.88.32.0/20; 0.0.0.0/0 10.88.40.0/22 \(I_1\)

c) — 6 points

The Bellman–Ford update is:

\[ \boxed{ d_u(t)=\min_{v\in N(u)} \left[c(u,v)+d_v(t)\right] }. \]

Here:

  • \(N(u)\) is the set of \(u\)’s neighbors;
  • \(c(u,v)\) is the direct link cost from \(u\) to neighbor \(v\);
  • \(d_v(t)\) is \(v\)’s advertised distance to destination \(t\);
  • \(d_u(t)\) is \(u\)’s resulting distance estimate.

Candidate costs:

Destination Via \(a\) Via \(b\) Via \(c\) Selected distance Next hop
\(x\) \(2+2=4\) \(5+7=12\) \(1+5=6\) 4 \(a\)
\(y\) \(2+8=10\) \(5+2=7\) \(1+8=9\) 7 \(b\)
\(z\) \(2+9=11\) \(5+4=9\) \(1+3=4\) 4 \(c\)

After \(c\) changes its advertisement for \(z\) to 12:

\[ \begin{aligned} \text{via }a &: 2+9=11,\\ \text{via }b &: 5+4=9,\\ \text{via }c &: 1+12=13. \end{aligned} \]

Therefore:

\[ \boxed{d_u(z)=9,\qquad\text{next hop}=b}. \]

The old distance of 4 is no longer supported by the current advertisements and must not be retained as an additional candidate.

d) — 2 points

Algorithm Information used by the router
Dijkstra A network topology graph with the relevant link costs
Distance vector Its direct-neighbor link costs and the distance vectors advertised by those neighbors

Dijkstra calculates paths from a topology map. A distance-vector update selects among neighbors using their advertised distances, without requiring a complete topology map.

payload bytes per fragment.

\[ 0/8=0,\qquad896/8=112,\qquad1792/8=224. \]

All Total Length values are at most 918 bytes, and the payload lengths sum to 2480 bytes.

No. The second fragment’s payload bytes, 896–1791, are still missing.

The output records are, in this required order:

parent 4

The child outputs its record before terminating. The parent’s waitpid returns only after that termination, so its output follows the child’s output.

The parent still has value = 4 because the child changes its own process-local copy. The child’s assignment does not modify the parent’s variable.

When the parent waits for the still-running child:

\[ \boxed{\text{Running}\rightarrow\text{Blocked}}. \]

When the child terminates and the parent becomes eligible to continue:

\[ \boxed{\text{Blocked}\rightarrow\text{Ready}}. \]

The parent does not necessarily execute immediately. It must subsequently be dispatched:

\[ \text{Ready}\rightarrow\text{Running}. \]

Both threads access the same shared variable in one process address space.
