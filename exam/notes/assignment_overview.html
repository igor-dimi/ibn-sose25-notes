Why Aufgabe 2 and Aufgabe 6 stand out

Aufgabe 2 is almost exactly the skill tested in the recent exam protocol. The protocol says that the Paging problem required students to create/fill page tables and determine logical and physical addresses, with PIDs and addresses given. Gedächtnisprotokoll_Klausur_ IB… That is essentially what Aufgabe 2 trains.

The 2016 exam is equally direct. It gives a logical address translated to a physical address, asks for its offset, page index and frame number, and then asks for the corresponding entries of both a normal and an inverted page table. ibn-klausur-2016

So for exam preparation I would treat Aufgabe 2 as mandatory.

Aufgabe 6 is even more striking. The 2016 exam asks for the memory requirement of a normal page table and then for the memory requirement of an inverted page table. ibn-klausur-2016 Moreover, the old 2012 minitest included in the same PDF asks:

  • maximum memory requirement of a page table without hierarchical tables;
  • what fraction of physical memory an inverted page table would require. ibn-klausur-2016

That is essentially Übung 5, Aufgabe 6, just with the parameters packaged slightly differently. So this is not merely “the same topic”; it is a historically demonstrated exam question form.

Aufgabe 1: important concept, less important packaging

The point of Aufgabe 1 is to make you understand the structural relationship

\[ \text{page number}\longrightarrow \boxed{\text{page table}}\longrightarrow\text{frame number}. \]

That is exactly the formulation used in the summary: the page number is the index, and the corresponding page-table entry contains the frame number. ibn-zusammenfassung

The student-residence analogy itself is unlikely to appear verbatim on an exam. But once you strip away the analogy, it tests two important questions:

  1. What does a direct page table actually represent?
  2. Why can a direct page table contain an enormous number of unused entries?

So I would understand it thoroughly but not spend much time rehearsing the dormitory analogy itself.

Aufgabe 3: TLB capacity + locality

This one is more sophisticated. You have a 4 KiB page, 4-byte integers, an array accessed with stride (M), and a TLB containing 64 entries. You have to reason about when successive array accesses hit different pages and when the working set exceeds the TLB capacity. ueb05-ibn-SS2025

The summary explicitly treats the TLB as a cache of page-table entries, including TLB hits/misses and the fact that only a small number of pages tend to be accessed frequently. ibn-zusammenfassung

So the knowledge is definitely syllabus material, but the exact “choose (M) and (N)” formulation looks more like a deeper exercise than a historically observed exam problem. I’d therefore study the reasoning, but not prioritize it above Aufgaben 2 and 6.

Aufgabe 4: TLB and context switches

This question tests an important consequence of the fact that different processes have different page tables.

The summary explicitly says that each process needs its own direct page table because different processes may use the same logical addresses while referring to different data. ibn-zusammenfassung

Therefore stale entries such as

\[ p \rightarrow f_A \]

from process A cannot normally simply remain valid when process B, which may map the same page (p) to (f_B), starts executing.

The “does this also apply to threads?” part is particularly useful because it checks whether you understand that threads of one process normally share the same address space.

This is a good short conceptual-exam-question style, even though neither of our two exam documents directly asks it.

Aufgabe 5: useful, but supplementary

This is the easiest one to deprioritize. It literally asks you to use the Address Translation Simulator and submit a screenshot. ueb05-ibn-SS2025

The translation process it illustrates is important. The activity itself is not.

For exam preparation I’d classify it:

Supplementary visualization exercise — do once if the mechanism is unclear; otherwise skip during final revision.

Aufgabe 7: very useful calculation pattern

This task combines two things:

\[ \text{expected access time} \]

and

\[ \text{locality / why TLB hit rates are high}. \]

The summary explicitly contains an expected-access-time calculation for a TLB:

\[ E[X]=h(1+T)+(1-h)(2+T) \]

for the simple one-level case, together with the interpretation of TLB hit and miss costs. ibn-zusammenfassung

Aufgabe 7 generalizes essentially the same reasoning to a (k)-level page table. ueb05-ibn-SS2025

That makes it quite valuable: it is not merely memorizing a formula—you need to reconstruct the formula from the number of memory accesses.

I would therefore consider it strong exam preparation, even though our two exam samples do not show this exact question.

Aufgabe 8: multilevel tables

This is the sheet’s most comprehensive page-table-structure problem. You have to divide a 32-bit logical address among:

  • page offset,
  • level-1 index,
  • level-2 index,
  • level-3 index,

and then determine the number of table entries and total maximum memory usage. ueb05-ibn-SS2025

The summary explicitly expects understanding of this structure: upper levels contain addresses of lower-level page tables, while only the lowest level plays the role of the ordinary direct page table. ibn-zusammenfassung

So this is core syllabus material. Its only downside from an exam-preparation perspective is that the exercise is rather extensive. An actual exam might split it into smaller subquestions.

Important distinction for Aufgabe 2

I would not treat the entire FAT simulator as something you must reproduce under exam conditions. Split it into two layers:

  • Exam-relevant: understanding the FAT representation, following a cluster chain, allocating clusters, calculating the number of required clusters and recognizing error cases.
  • Mostly practical: designing the class, writing complete code, testing it and printing outputs.

Thus, Aufgabe 2 is simultaneously very important in subject matter and not very exam-like in its full implementation format.
