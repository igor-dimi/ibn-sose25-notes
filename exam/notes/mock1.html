Suggested working time: approximately 90 minutes
Total points: 84
Number of tasks: 7
Conditions: Closed book; a basic calculator is permitted.

Show your reasoning and intermediate calculations unless a question explicitly requests only a result. Give units for numerical answers. Use \(1\,\mathrm{KiB}=2^{10}\) bytes, \(1\,\mathrm{MiB}=2^{20}\) bytes and \(1\,\mathrm{kB}=1000\) bytes. All indices and byte offsets start at zero.

Aufgabe 1

10 points

One process executes the following C-like code. Every fork() succeeds. Variables are ordinary process-local variables; no shared memory is used. emit(x) outputs the current value of x exactly once, without buffering effects.

int x = 1;

for (int i = 0; i < 2; i++) {
    pid_t r = fork();                 // F
    if (r == 0) {
        x = x + i + 1;
        break;
    }
    x = x + 10;
}

if (x < 10) {
    fork();                          // G
}

emit(x);

a) — 5 points

Draw the complete process tree, labeling every creation edge with the call site and, for call F, the loop iteration.

State:

  • the total number of processes created, including the original process;
  • the meaning of the return value of call F in its parent and child;
  • which processes execute call G.

b) — 2 points

Give the value output by each process and the total number of output operations. Is the order of these outputs uniquely determined?

c) — 3 points

Name the five states of the basic process-state model.

Give the state transition associated with each event:

  1. A running process requests a blocking disk read.
  2. That disk read completes.
  3. A running process exhausts its CPU quantum.

Aufgabe 2 — 18 points

a) — 4 points

The page size is:

\[ 512=2^9\text{ bytes}. \]

Therefore:

\[ \boxed{\text{Offset: }9\text{ bits}},\qquad \boxed{\text{Virtual-page number: }18-9=9\text{ bits}}. \]

The number of physical frames is:

\[ \frac{128\cdot1024}{512}=256=2^8. \]

A full normal page table has one entry per virtual page:

\[ 2^9\cdot4=2048\text{ bytes} =\boxed{2\text{ KiB per process}}. \]

The inverted page table has one entry per physical frame:

\[ 256\cdot8=2048\text{ bytes} =\boxed{2\text{ KiB system-wide}}. \]

This excludes auxiliary structures, as specified.

b) — 4 points

PID Virtual page Allocated? Present bit Frame
17 0 Yes 1 9
17 3 Yes 1 2
17 7 Yes 0 —
28 1 Yes 1 6
28 4 Yes 1 2

All other virtual pages are unallocated under the stated snapshot.

PID 17’s page 7 belongs to its allocated address space but is currently absent from RAM. Accessing it can trigger loading by the operating system.

An unallocated page does not belong to an allocated region. Accessing it is an invalid access under the given model.

Both may have a present bit of zero, so the present bit alone does not distinguish them. The distinction requires other page-table information or operating-system metadata.

c) — 4 points

Use:

\[ p=\left\lfloor\frac{V}{512}\right\rfloor,\qquad d=V\bmod512,\qquad A=f\cdot512+d. \]

PID Virtual address Virtual page Offset Physical address or event
17 1605 3 69 \(2\cdot512+69=\boxed{1093}\)
28 2117 4 69 \(2\cdot512+69=\boxed{1093}\)
17 3588 7 4 Page fault: allocated page is not resident

For the final access, no physical data address can be determined from the snapshot. The frame chosen when loading the page is unspecified.

d) — 3 points

Frame 2 is shared by:

\[ (\mathrm{PID}=17,\ p=3) \quad\text{and}\quad (\mathrm{PID}=28,\ p=4). \]

An inverted entry containing only one (PID, virtual page) pair cannot represent both mappings simultaneously.

One possible extension is an alias list associated with the frame, recording every (PID, virtual page) mapping to it.

For physical address 1100:

\[ 1100=2\cdot512+76. \]

Thus the corresponding virtual addresses are:

PID Virtual page Virtual byte address
17 3 \(3\cdot512+76=\boxed{1612}\)
28 4 \(4\cdot512+76=\boxed{2124}\)

e) — 3 points

Here, kB is decimal:

\[ 7.5\text{ kB}=7500\text{ bytes}. \]

Required pages:

\[ \left\lceil\frac{7500}{512}\right\rceil =\boxed{15}. \]

Allocated space:

\[ 15\cdot512=\boxed{7680\text{ bytes}}. \]

Unused final-page space:

\[ 7680-7500=\boxed{180\text{ bytes}}. \]

Aufgabe 3 — 10 points

a) — 4 points

One violating interleaving is:

Step Thread and instruction \(r_A\) \(r_B\) available Result
1 A: instruction 1 1 — 1
2 B: instruction 1 1 1 1
3 A: instruction 2 1 1 1 Continues
4 B: instruction 2 1 1 1 Continues
5 A: instruction 3 0 1 1
6 B: instruction 3 0 0 1
7 A: instruction 4 0 0 0
8 B: instruction 4 0 0 0
9 A: instruction 5 0 0 0 SUCCESS
10 B: instruction 5 0 0 0 SUCCESS

Both calls succeed despite there being only one available reservation.

The final value of available is zero, but that value hides the fact that two reservations were promised.

b) — 4 points

Use one shared semaphore initialized to 1:

shared Semaphore m = 1

reserve() -> Result:
    wait(m)

    int r = available

    if r <= 0:
        signal(m)
        return FAILURE

    r = r - 1
    available = r

    signal(m)
    return SUCCESS

The entire read–check–update operation is protected.

Required semaphore semantics:

  • wait(m) atomically acquires a permit if one is available; otherwise the caller blocks until it can acquire one.
  • signal(m) releases a permit, allowing a waiting thread to proceed if one exists.

Both return paths release the semaphore.

c) — 2 points

No. Protecting only the store does not protect the earlier read and decision.

Both threads can read available = 1, pass the check and privately calculate \(r=0\). They then acquire the semaphore one after another, each store zero, and both return success.

Serializing the writes does not make the complete reservation operation atomic.

a) — 3 points

Label the instances \(X_1,X_2,X_3\) and \(Y_1,Y_2\).

Allocation edge Meaning
\(X_1\to P_1\) \(P_1\) holds one \(X\)

Request edge Number of instances requested
\(P_1\to Y\) 1

Requests target a resource type, since instances of that type are interchangeable. The graph can be represented compactly as:

A directed cycle is:

\[ P_1\rightarrow Y\rightarrow P_2\rightarrow X\rightarrow P_1. \]

Because there are multiple instances per resource type, this cycle does not by itself establish a deadlock.

b) — 3 points

With columns \((X,Y)\):

\[ \boxed{E=(3,2)}. \]

The allocation matrix is:

\[ \boxed{ C= \begin{pmatrix} 1&0\\ 1&1\\ 0&1 \end{pmatrix} }. \]

The current additional-request matrix is:

\[ \boxed{ R= \begin{pmatrix} 0&1\\ 1&0\\ 2&0 \end{pmatrix} }. \]

The total allocation is:

\[ \sum_i C_i=(2,2). \]

Therefore:

\[ \boxed{A=E-\sum_i C_i=(3,2)-(2,2)=(1,0)}. \]

c) — 4 points

Initially, only \(P_2\)’s complete request can be satisfied.

Step Selected process Request \(A\) before \(A\) after Marked processes
1 \(P_2\) \((1,0)\) \((1,0)\) \((2,1)\) \(\{P_2\}\)
2 \(P_1\) \((0,1)\) \((2,1)\) \((3,1)\) \(\{P_1,P_2\}\)
3 \(P_3\) \((2,0)\) \((3,1)\) \((3,2)\) \(\{P_1,P_2,P_3\}\)

After \(P_2\) is marked, both remaining processes are eligible. The lowest-index rule selects \(P_1\).

The update after each selected process is:

\[ A_{\text{after}}=A_{\text{before}}+C_i. \]

The requested resources are temporarily acquired and then returned; the net increase is the process’s original allocation.

All processes can be marked, with completion sequence:

\[ \boxed{P_2,\ P_1,\ P_3}. \]

Therefore, there is no deadlock in the given situation under the stated assumptions.

d) — 2 points

The four Coffman conditions are:

  1. Mutual exclusion: a resource instance cannot be shared simultaneously.
  2. Hold and wait: a process retains resources while requesting others.
  3. No preemption: allocated resources cannot be forcibly taken away.
  4. Circular wait: processes form a cycle of resource dependencies.
